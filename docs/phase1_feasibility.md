# Phase 1 — Environment and feasibility

Completed on 2026-11-03 UTC. No later phase is authorized or executed.

- Created the `formatter-suppression-study` Git repository on branch
  `codex/phase1-feasibility` and a local isolated `.venv`.
- Installed Black 25.1.0, Ruff 0.11.13, pytest 8.3.5 and setuptools 80.9.0
  under CPython 3.11.9 on Windows x64. Saved exact transitive dependencies.
- Verified installed version/help output, required CLI options, and `pip check`.
  All seven recorded tool-verification checks succeeded.
- Implemented strict AST comparison, bounded formatter/linter subprocesses,
  four-pass JSON measurement, within-source suppression subtraction, and
  failure/invalid-source records. Implemented minimal `format` and `compare` CLI.
- Preserved source pairs, raw tool output, invocation records, AST dumps,
  checksums and environment metadata. Exported full JSONL and summary CSV.
- Executed a single AI-authored fixture through both formatters, then repeated
  both measurements. Repetitions are reproducibility checks, not additional cases.
- Ran actual-tool integration and unit tests. Final verification artifacts are
  `reports/phase1/pytest.xml`, `pytest.txt`, `implementation-lint.txt`, and
  `evidence_checks.json`.

## Measured observations

Primary evidence is in `datasets/results/phase1`. There are **two formatter
comparisons on one controlled input**, not two independent source cases.

| Formatter | Text changed | AST equal | A visible before | B underlying before | C visible after | D underlying after |
|---|---|---|---:|---:|---:|---:|
| Black 25.1.0 | Yes | Yes | 1 | 3 | 1 | 3 |
| Ruff 0.11.13 | Yes | Yes | 1 | 3 | 1 | 3 |

For each source snapshot, the multiset subtraction identifies two suppressed
diagnostics. The original fixture contains `import os` suppressed by F401 noqa,
`missing_name` suppressed by F821 noqa, and one visible undefined-name diagnostic.
Raw records show formatting moved diagnostic source coordinates. Line movement
alone is not suppression drift.

Both primary trials completed all four lint passes without tool or AST failures.
Both remain conservatively classified **Ambiguous** because cross-transformation
diagnostic matching is not implemented. Newly hidden/exposed counts are null.
**No independently verified suppression-drift finding is claimed.** Equal counts
are only a feasibility observation, not proof of unchanged suppression coverage.
No prevalence estimates, confidence intervals or formatter superiority claims are
supported by this one fixture.

`datasets/results/phase1-repeat` retains a second execution of the same two
formatter comparisons. The verification script checks source/output hashes,
counts, AST status and diagnostic content after ignoring only execution-specific
temporary filenames. It also checks exported JSONL against individual records,
CSV IDs/output hashes, raw JSON diagnostic stdout and source checksums.

The supplied-pair CLI was exercised separately and is not included in the two
primary trials. Its first invocation used an incorrect default AI-origin flag;
the retained `phase1-cli-compare/provenance_correction.json` explicitly corrects
that metadata without changing the original evidence. The CLI now records unknown
AI provenance as null unless `--ai-assisted` is supplied. A subsequent CLI check
passes explicit fixture provenance. Measurement results were unaffected.

## Limitations and handoff

The example is an AI-assisted controlled smoke fixture, not natural repository
evidence or a positive drift control. Tests and repeated runs are not research
sample observations. There is no dataset generator, configurable experiment
runner, structural matcher, validated drift classifier, statistical analysis,
completed literature review, research report or explorer.

The initial test run had two failures caused by temporary filenames in
repeatability assertions; the documented harness fix retained all other diagnostic
fields. All 19 tests passed after correction. Two unused imports found during the
implementation lint check were corrected. Raw help output contains whitespace
generated by Ruff; it is preserved rather than edited to satisfy whitespace checks.
Git attributes prevent newline conversion of retained evidence.

The implementation baseline recorded by the primary trials is commit
`fe2a39a`; the working tree was dirty because evidence and preservation attributes
were being added. Subsequent changes clarify optional source-provenance metadata
and add the evidence verification script; they do not introduce diagnostic
matching or alter the four-pass commands. Initial tooling evidence predates the
first commit and correctly records a null commit.

Phase 2 should read the protocol and existing code, implement structural
diagnostic correspondence and outcome classification, and validate independently
justified controls. Only after that gate should main dataset generation begin.
